# 実機で検証できない機種は移植しない

Go 版が最初に持つ機種プラグインは `stealth` と `vb` だけにする。手元に実機があるのがこの 2 機種
だからで、残る `uforush` / `ghostneo` / `xfiles` は移植可能だが**保留する**。

理由は、検証できない移植はバグを Go に翻訳するだけになること。とくに `uforush` は大当り区間の
経過時間からラウンド数を逆推定しており（55 秒未満なら 1R、136 秒未満なら 8R…）、実機の信号
タイミングが無ければ正しさを確認する手段が無い。`xfiles` の「UFO-ZONE 中に 5 回転を超えたら
直撃 XTRA-RUSH だったと判定する」も同種のヒューリスティックである。将来これらの実機が手に
入ったときに、生信号ログを録ってから移植する。

検証手段は 2 段構え。集計ロジックは手書きのポート値の列を流す table-driven テストで、機種の
挙動は**実機で録った生信号ログを fixture としてリポジトリにコミットして**再生で検証する
（「初当たり→SR 突入→連荘→転落」のような区間を切り出す。数 KB）。旧実装にテストが無かったのは
実機と台の挙動なしには検証できなかったためで、ログを資産化することでこれを外す。

この方針から実装順序も決まる。最初に作るのは集計でもフロントでもなく、**信号源から生信号を
JSONL に落とすところまで**とし、実機に繋いで `stealth` を回してログを得る。それ以降の開発は
記録再生の信号源（ADR-0005）に差し替えるだけですべて机の上で完結し、集計規則を直すたびに
台の前へ戻る必要がなくなる。
