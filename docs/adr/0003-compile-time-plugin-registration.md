# 機種プラグインは動的ロードせず、コンパイル時に登録する

「プラグイン」と呼びながら動的ロードをしない。Go 標準の `plugin` パッケージは公式ドキュメント
自身が Linux/FreeBSD/macOS 限定であること、ホストとプラグインがツールチェイン・ビルドタグ・
依存ソースまで完全一致していなければクラッシュすること、そして「IPC の方が適している」ことを
明記しているため採らない（https://pkg.go.dev/plugin）。

外部プロセス・WASM・組み込みスクリプトも検討したが、機種差は設定値ではなく**アルゴリズムの差**
である（`xfiles` は「UFO-ZONE 中に 5 回転を超えたら直撃 XTRA-RUSH だったと判定する」という
ヒューリスティックを持ち、`uforush` は大当り区間の経過時間からラウンド数を逆推定する）。
つまり「動的に追加したい」場面は常に「コードを書く」場面と一致しており、再ビルドの手間が
実質ゼロである。機種追加の実績も 10 年弱で 5 機種。

代わりに単一静的バイナリとクロスコンパイルを取る。プラグイン境界はインタフェースとレジストリ
として明示的に残すので、将来スクリプト方式を足す場合も「スクリプト実行器を 1 つのプラグイン
実装として登録する」形で後付けできる。
