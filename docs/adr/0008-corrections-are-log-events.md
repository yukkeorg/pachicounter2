# 手動補正は信号ログ上のイベントとして記録する

回転の取りこぼしは 5ms ポーリングとデバウンスでも原理的にゼロにはできず（USB の転送遅延、
台の接点の劣化、配線の接触不良）、1 つ取りこぼすとそのセッションの残り全部で数字がずれ続ける。
旧実装には補正手段が無く、`-r` で全部リセットするしかなかった。配信中にこれは使えない。

そこで補正を許すが、スナップショットを直接書き換える形は採らない。ADR-0006 で「生信号ログが
唯一の真実で、スナップショットはその導出物」という関係を作ったので、値を直接書き換えると
再集計で補正が消え、再集計そのものが信用できなくなる。

補正は信号イベントと同じ JSONL に `{"type":"correct", "counter":..., "delta":..., "note":...}`
として追記し、再集計時にも順序通り適用する。操作は `POST /correct`（配信中に手元から押せる
必要がある）。

補正できる対象は共通スキーマのカウンタだけに限る。機種プラグインの内部状態（`xfiles` の状態
機械、`uforush` の経過時間）まで外から触れるようにすると、プラグインが自分の不変条件を
守れなくなる。

旧 Python 版のデータファイル（`~/.config/pcounter.d/<機種名>`）は引き継がない。`totalcount` が
通常時回転数なのか総回転数なのかが機種ごとに違い（ADR-0004）、機械的に変換できないため。
