# 操作コマンドはコアと同じバイナリのサブコマンドにする

配信中に手元から補正や新しいセッションの開始を頼む操作コマンドを、`pachicounter` のサブコマンド
（`correct`、`session new`、`status`）として持つ。サブコマンドが無ければ、今までどおりコアが起動する。
操作コマンドはコアと同じ PC で使うので、配る物を単一静的バイナリ 1 本のまま（ADR-0005）にしておく
ことを優先した。

別バイナリ（`pachicounter-ctl`）にすればコアのコマンドラインに手を入れずに済むが、Makefile と
配布物が 2 本になる。コアの起動も `serve` などのサブコマンドにそろえる案は、形は一貫するものの、
README や起動スクリプトにあるコアの起動方法を変えるほどの利点が無い。

同じバイナリに同居させる代わりに、知らない位置引数はエラーにする。これまでコアは位置引数を黙って
無視していたため、操作コマンドのつもりの打ち間違い（`pachicounter corect …`）で 2 つ目のコアが
起動し、動作中のコアのセッションを続きとみなして、そのログに resume を書くことを再現で確かめた。
