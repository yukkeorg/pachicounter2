# コアを常駐 HTTP サーバとし、フロントを SSE で接続する

本来の用途は配信画面へのオーバーレイ合成（`~/Documents/Pachi/broadcast_system.svg`）であり、
今の現実的な合成手段は OBS のブラウザソース、すなわち URL を渡せることが必須である。
そこでコアを常駐 HTTP サーバとし、集計結果のスナップショットを SSE で push、制御は POST で受ける
構成にした。WebSocket ではなく SSE なのは、データが実質一方向であり（先行試作の pcounter.js も
片方向しか使っていなかった）、`EventSource` の自動再接続によって「フロントを気軽に増やす・
落とす・作り直す」がフロント側のコードなしで成立するため。

旧実装の「stdout に NUL 区切り JSON」は、フロントがコアの子プロセスに縛られ、複数同時接続も
再接続もできないため採らない。

待ち受けは既定で `127.0.0.1`。台のデータを LAN に晒すのは明示的な指定があったときだけとする。
