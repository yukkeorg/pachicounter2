# 初回読み取りではエッジを発火せず、デバイス切断でも落ちない

**初回読み取りは基準値として取り込むだけで、エッジを発火しない。** 旧実装は前回ポート値を
`-1`、スイッチ状態を `0` で初期化していたため（`core.py:105`）、最初の読み取りで立っている
ビットを全部「立上り」として発火していた。大当り中にコアを起動すると、その瞬間に大当り回数が
1 増える。デバイスを抜き差しして再起動するたびに数字が増える。エッジ検出を素朴に書くと同じ
初期化に戻ってしまうので、意図的な仕様として記録する。デバイス再接続時も同様に、その時点の
値を新しい基準とする（切断中の変化は原理的に取り逃しているため）。

**デバイスが繋がっていなくても起動し、接続を待ち続ける。** 旧実装は起動時にデバイスが無いと
即終了していた（`app.py:64-68`）。配信中にコアが落ちるとセッションの数字を失うリスクを負い、
ADR-0006 で作ったクラッシュ耐性の意味が薄れる。接続状態はスナップショットに含めて
（`"device": {"connected": false}`）フロントで分かるようにする。先行試作の pcounter.js も
検出をリトライし続ける形だった（`usbio2.js:50`）。

機種は起動引数で指定し、切替は再起動とする。動的な切替は、機種が変わればセッションも必ず
新規になるため、「セッションは明示操作で切る」（ADR-0006）と二重管理になる。ただし起動時に
セッションを継続する際、記録された機種と引数の機種が違えば自動で新セッションにする。
別機種の数字が同じセッションに混ざるのが最悪のケースだから。

経過時間は単調増加クロックで測る。旧実装の `DeltaTime` は壁時計（`time.time()`）だったため、
NTP の時刻補正で経過時間が飛び、`uforush` のラウンド数逆推定が誤りうる。
